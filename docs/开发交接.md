# KeRing 开发交接说明

**这是项目唯一的技术文档。接手开发、改代码、部署之前请完整读一遍。**
它记录了：环境要求、技术选型的理由、项目结构、不能违反的约定、待办、已知风险，以及前人踩过的坑。

---

## 一、这是什么 · 现在什么状态

教室一体机用的打铃程序。读课表，在**每节课开始前 7 分钟**播报
「下节课，×××，请同学们做好课前准备」（提示音 + 语音）。

**当前状态：功能完整、可交付、可运行。**

| 事项 | 状态 |
| --- | --- |
| 功能开发 | 完成（见下方功能清单） |
| 单文件打包 | 完成：一个 exe（约 1 MB，依赖和铃声都在里面） |
| 接入正式课表接口 | **已完成**，走学校 `dktkView.php`；细节见 [课表接口采集方案.md](课表接口采集方案.md) |
| 低年级作息的真实时间 | **已完成**，两套作息都取自学校给的《作息时间表（2026 年秋季学期）》 |
| 换机测试（教室机器实测） | 未做 |

### 功能清单

- 周课表显示：行 = 第 1..N 节（含作息时刻），列 = 周一到周日
- 班级选择：数据源给的是**全校课表**，首次运行选一次班级，之后一直记住；设置里可随时切换
- 正在上的课标红、下一个提醒点标绿、**被调课动过的格子标蓝字**
- 上午/下午之间有一条深蓝分隔色带（位置可配）
- 周六周日没有课时自动隐藏两列，窗口宽度跟着收窄
- 每节课前 7 分钟播报（分钟数可配；**一句话默认连念 3 遍**，遍数可配）
- **作息方案跟着班级走**：一二年级用低年级时间表，三到六年级用高年级时间表，不用手工选
- 播报前把系统音量临时提到设定值，播完恢复原值（含静音状态）
- 托盘常驻、关窗不退出、开机自启（默认开）
- 单实例（整机唯一）、静音开关、手动更新课表、手动测试播报
- **自动校时**：按 NTP → 教务接口 → 本机 的优先级取时间，教室机器钟不准也能准点打铃
- **取数失败有三层兜底**：短退避重试（1→2→5→10 分钟）／开机先用上次成功的课表缓存顶上／
  周一到周五出现空课表时不覆盖现有数据
- 换铃声（母本进仓库、内嵌进 exe、现场可替换）
- 无界面自检 `--selftest`、单次播报 `--say`
- **播报次数可配**（`AnnounceRepeatCount`，默认 3、范围 1~10）：每遍都是"先响一次提示音、再念这句话"，
  两遍之间停 700ms。个人版（KeRing_SOLO）先加的，2026-09-16 班级版跟着加，两边行为一致
- **悬浮窗**（2026-09-16 加，跟个人版同一套）：桌面上常驻一个小窗显示**今天**的课，
  鼠标移上去（或点一下）在旁边弹出**全周预览**，离开就收回；**默认显示、默认不置顶（沉在下面）**，
  表头上的**图钉**切置顶 / 沉底。详见第五节"悬浮窗"那条

## 二、开发环境要求

| 项目 | 要求 / 本机现状 |
| --- | --- |
| 操作系统 | Windows（只用 Windows 专属能力：WinForms、System.Speech、Core Audio） |
| .NET SDK | 本机 8.0.425。用 `dotnet build` 即可，**不需要 Visual Studio**（net472 用任意 6.0+ SDK 都能编） |
| 目标框架 | `net472`（.NET Framework 4.7.2） |
| 编译用的引用程序集 | 由 NuGet 包 `Microsoft.NETFramework.ReferenceAssemblies` 提供，所以没装 VS 也能编 |
| IDE | VS Code 或 Visual Studio 2022 都行。**界面全部用代码构建，没有 `.Designer.cs`，不依赖设计器** |
| 运行环境 | Win10 1803 以后 / Win11 **自带** 4.7.2+，目标机不用装任何东西；Win7 需装一次 |

编译验证：

```
dotnet build -c Release
```

## 三、技术选型（以及为什么是这些）

| 项目 | 选型 | 备注 |
| --- | --- | --- |
| 语言 / UI | C# + WinForms | 代码构建界面，不用设计器；原生托盘、表格，开发量最小 |
| 目标框架 | **.NET Framework 4.7.2** | 见下方"为什么不用 .NET 8/10" |
| 语言版本 | `<LangVersion>latest</LangVersion>` | 不显式设会退回 C# 7.3，现代写法直接编不过 |
| Nullable / ImplicitUsings | 都关闭 | net472 上隐式 using 会引来找不到类型的编译错误 |
| 语音合成 | **System.Speech**（框架自带，SAPI5） | **不是 NuGet 包**，用 `<Reference Include="System.Speech" />` 引用 |
| 音量与播放 | **NAudio 2.2.1** | Core Audio API 控制系统音量；播放提示音 |
| 配置与课表解析 | **Newtonsoft.Json 13.0.3** | |
| 单文件打包 | **Costura.Fody 6.0.0** | 把依赖的托管程序集嵌进 exe，运行时从内存加载 |
| 定时 | `System.Timers.Timer`，1 秒轮询 | 每次按系统时钟重算，不累加间隔（避免漂移） |
| 时间基准 | 自写的极简 SNTP + 教务接口的 `Date` 头（`App/AppClock.cs`、`App/NtpClient.cs`） | 教室机器的钟不一定准；只算修正量，**不改系统时钟**。不引任何依赖，见约定 13 |
| 自启 | `HKCU\...\Run` | 不需要管理员权限 |
| 单实例 | `Global\` 命名 Mutex + 命名事件 | 整机唯一；命名事件用来唤出已有窗口 |

### 为什么不用 .NET 8 / 10

- Windows 自带的是 **.NET Framework**，不含 .NET 8/10。用新版就得自包含，**52 MB 自包含单文件 vs 现在约 1 MB**
- .NET 8 及以上**完全不支持 Win7**；4.7.2 兼容到 Win7（装一次即可）
- 定 4.7.2 而不是 4.8：4.7.2 的程序在 4.8 机器上照跑，反过来不行。Win10 1809 LTSC 这类一体机常见系统自带 4.7.2，**定低一档覆盖更广**
- 代价：生态偏旧、少数新语法要垫片。本项目的需求用不到新特性

### 单文件是怎么做到的

.NET Framework **没有**官方单文件发布。这里用 `Costura.Fody` 把依赖的托管程序集作为资源嵌进 exe，
运行时通过 `AssemblyResolve` 从内存加载。`FodyWeavers.xml` 里一行 `<Costura />` 就是全部配置。

**前提是所有依赖都是托管程序集**——本项目满足（NAudio 全是托管代码，通过 P/Invoke 调系统 API，没有原生 dll）。

## 五、关键约定（改代码前必须知道）

这几条是评审时和使用方逐条确认下来的，**不要凭直觉改**：

1. **时刻由程序里的作息方案表决定，课表数据只提供"星期几、第几节、上什么课"。**
   数据源不知道这台机器属于哪个年级，所以 `App/GradeSchemes.cs` 是时刻的唯一来源，
   数据里即使带了 `start/end` 也会被覆盖（见 `MainForm.BuildScheduleView`）。
   **用哪一套由班级决定**：`GradeSchemes.SchemeForClass` 从班级名首字判断（一/二 → 低年级，
   三/四/五/六 → 高年级），`BuildScheduleView` 每次都会照它校正 `AppConfig.GradeScheme`。
   时间表本身取自学校给的《作息时间表（2026 年秋季学期）》，只含第 1~6 节正课。

2. **数据源以 `IScheduleSource` 为界。** 取数和解析都封在实现类里，上层只认这个接口。
   现在有两个实现：`HttpScheduleSource`（学校接口，正式用）和 `LocalFileScheduleSource`（本地演示文件）。
   **选哪个由配置决定**——`ScheduleSourceFactory` 看到 `ScheduleApiUrl` 非空就走接口，否则退回本地文件。
   换数据源只改配置，不碰代码。接口本身见 [课表接口采集方案.md](课表接口采集方案.md)。

3. **单实例是整机唯一的**（`Global\` 命名锁）。一台机器只允许一个实例，即使程序被拷到两个目录、
   或同一账号在另一个会话（远程桌面）再次登录。拿不到全局权限时才退回本会话锁，并写日志。

4. **音量是"临时提升 + 原样恢复"。** 提升和恢复都写在 `Announcer.Announce` 里，
   恢复在 `finally`，包含静音状态。**不要改成启动时永久拉满**——会覆盖用户设置。

5. **静音只在本次运行有效**，重启自动恢复不静音。这是故意的：静音被遗忘会导致铃长期不响还没人发现。

6. **错过的打铃点不补播**，只记日志（`Scheduler.Rebuild` 会把过去的点标记为已触发）。

7. **周六周日作为一组**：都没有课就一起隐藏，任一天有课就一起显示；
   并且**窗口宽度跟着可见天数走**（列宽固定 124），不是把剩下的列拉宽。

8. **所有界面尺寸都走 `UiScale.S(...)`**，不要直接写像素值。
   WinForms 的自动缩放在这套代码上不可靠（见下方"踩过的坑"）。
   **字号是例外，走 `UiFont`**（`UI/UiFont.cs`）：字号用"磅"，会随屏幕 DPI 自动放大，
   再过一遍 `S()` 就成了放大两遍。**改字号只改 `UiFont` 那一张表**，别在界面代码里写死磅数。

9. **程序不往自己旁边写任何东西。** 运行时文件都放数据目录（见下一节），
   因为程序是单文件，要能在只读目录里跑。

10. **`schedule.json` 只是演示数据。** 只有配置里没有 `ScheduleApiUrl` 时程序才会读它，
    正式部署必须把接口地址配好。

11. **数据源给的是全校课表，这台机器只认一个班级。**
    班级由 `AppConfig.SelectedClassId` 记住：
    - 配置里为空 = 第一次运行 → 数据取到后弹一次"选择班级"（`ClassPickerForm`，不可取消）
    - 选过之后一直记住，重开不再问；在设置对话框里可以随时切换
    - 选定的班级在数据里找不到时（改名/删班）**不弹窗**，自动退回第一个班并记日志
      —— 后台刷新时弹窗会打断无人值守运行，所以只在首次选择时弹
    - 首次选择的弹窗放在 `OnShown` 之后弹：在 `OnLoad` 里开模态框会把主窗口的显示流程挡住
    - 班级 id 直接用班级名（学校接口只给 `className`，没有稳定 id）；
      代价是学校改班级命名会让每台机器要重选，这一点记在方案文档的待确认清单里

12. **取数一律在后台线程做，不要在 UI 线程上同步等。** 课表来自 HTTP 接口，网络不通时最坏要等满
    超时（10 秒 × 2 次重试）才报失败；放在 UI 线程上会让窗口僵住，一体机上看起来就像死机。
    `MainForm.RefreshSchedule` 只负责发起，结果回到 UI 线程由 `ApplyScheduleResult` 应用，
    靠 `_refreshRunning` 防重入（按钮、托盘菜单、定时器三个入口都会调它）。

13. **要"现在几点"一律用 `AppClock.Now`，不要用 `DateTime.Now`。** 教室机器的系统时间不一定准
    （主板电池没电、时区设错、从没同步过），用系统时间打铃会让铃整体早/晚。
    `AppClock` 按 **NTP → 教务接口的 HTTP Date 头 → 本机系统时间** 的优先级算一个修正量，
    打铃、界面显示、日志时间戳全部走它。
    - **只加修正量，不改系统时钟**：改系统时间要管理员权限，而且第二个源本身也不完美
    - 时间**一律按北京时间（UTC+8）**换算，所以系统时区设错也不会让铃差 8 小时；
      时区不对会在日志和自检里报出来
    - 教务接口那台服务器实测**慢 14 秒**，所以它只在偏差超过 1 分钟（本机钟明显坏了）时才被采用，
      免得把一个本来准的钟带偏
    - 新增代码如果用到时间，别自己写 `DateTime.UtcNow`/`DateTime.Now`，用 `AppClock`

14. **悬浮窗只是"同一份课表的另一个视图"，它不自己取数、不自己算提醒。**
    `MainForm.PushFloating` 每秒把 `_schedule` + `_scheduler.NextReminder` 推过去；
    "格子里写什么、什么颜色、哪一节正在上"三个规则统一在 `UI/ScheduleRender.cs`，
    主窗口和预览共用——两边各写一套的话会慢慢长歪，产出的就是"两处显示不一致"这种最难查的问题。
    它**默认显示**、**默认不置顶（沉在最下面）**，表头图钉切置顶 / 沉底（见本节"悬浮窗"）。

### 班级设计（这台机器服务哪个班）

**三个概念不要混：**

| 概念 | 决定什么 | 谁提供 | 存在哪 |
| --- | --- | --- | --- |
| 数据源（全校课表） | 全校所有班级 + 每班的课程表 | 使用方的接口 | 每次刷新时取，**不落盘** |
| **班级** | 这台机器用**哪个班**的课程内容 | 首次运行时人工选一次 | `AppConfig.SelectedClassId`（每台机器独立） |
| 作息方案 | 每节课**几点上、几点下** | 程序内置两套，**由班级决定用哪套**（一二年级低年级、三到六年级高年级） | `AppConfig.GradeScheme`（自动写入，不用手工选） |

一句话：**数据源给全校 → 这台机器认一个班 → 这个班的课表配上本机的作息方案
= 屏幕上的周课表 + 打铃点。**

**各种场景下的行为：**

| 场景 | 行为 |
| --- | --- |
| 第一次运行（配置里没有班级） | 课表取到后弹一次选班框；**不能取消**，必须选一个；选完立刻写进配置 |
| 之后每次启动 | 直接用记住的班级，不弹任何框 |
| 在设置里切换班级 | 点"班级"那一行 → 弹出同一个选班框（这次可以取消）→ 确定后**立刻**重算课表与打铃点，不用重启 |
| 班级在数据里找不到了 | 自动退回第一个班并记日志，**不弹窗**（后台刷新时弹窗会打断无人值守运行） |
| 数据里一个班都没有 | 课表加载判为失败，界面显示失败原因，保留上一次的内容 |

**几个刻意的设计决定：**

- **用 `id` 记班级，不用名字。** 学校改班级命名（"一(1)班" → "一年级1班"）不会让每台机器都要重选；
  只有 id 变了才算换班。
- **选班框放在窗口显示之后弹**（`OnShown`），不在 `OnLoad` 里弹——实测过，在 `OnLoad` 里开模态框
  会把主窗口的显示流程挡住，看起来像程序根本没启动。
- **一台机器一个班**：`SelectedClassId` 存在本机配置里，所以同一份 exe 拷到不同机器，各自选各自的班。
- **状态栏常显当前班级**，管理员走到机器前一眼能看出这台是给哪个班打铃的。
- **选班框是可滚动的列表**（每行 52 逻辑像素，一体机上手指点得准）。全校班级如果很多（几十个），
  以后可以考虑按年级分组或加筛选，现在 9 个班一屏看全。

**已定：作息方案不再手工选，直接跟班级挂钩。** 一二年级用低年级时间表，三到六年级用高年级时间表，
由 `GradeSchemes.SchemeForClass` 从班级名推出来（学校班名形如"一(1)""三(4)"，取首字判断）。
设置对话框里那一行还在，但改成**只读显示**，让管理员看得见这台机器用的是哪套时间。
班名认不出年级时（学校改名等）保持原配置不动，不乱猜。

### 悬浮窗（今天的课 + 鼠标移上去看全周）

**要什么**（使用方 2026-09-16）：桌面上常驻一个小窗显示**今天的课**；鼠标移上去**自动放大预览全周**。
**默认显示**（`AppConfig.FloatingEnabled` 默认 `true`），并且**默认不置顶**——
也就是说它默认**沉在最下面**，会被别的窗口盖住（上课放全屏课件时不挡人）；
要它常显就点表头那个**图钉**把它钉在最上面（`AppConfig.FloatingTopMost`，状态会记住）。

**两种状态**

| | 平时（小窗） | 鼠标移上去（预览） |
| --- | --- | --- |
| 内容 | **今天**的课，按上课时刻排成一行一节 | **全周**课表（跟主窗口同一套规则：没课的周末收起、上下午色带、调课蓝字） |
| 尺寸 | 宽 **124** 逻辑像素，高 = 34 + 行数×30（没课就矮） | 宽 96+5×96，高 30 + 行数×38（自己算） |
| 配色 | 红底=正在上、绿底=下一个提醒点 | 同上 |
| 表头 | 只有左边"今天 周三"和右边的**图钉** | 无（预览自带标题栏） |
| 脚注 | **无** | 无 |

**班級版的小窗只有"表头 + 今天的课"两样东西**（使用方 2026-09-16 定的）：
**没有脚注那行**（原先是"下次 14:58 第6节 科学"／快到点写"还有 N 分钟"），
**表头也没有右上角的时刻**——要看时间看系统右下角就行，小窗越小越不挡人。
代价是"下一个提醒点是哪节"看不到了；要看得回主窗口的状态栏，或者把鼠标移上去看全周预览
（预览里下一个提醒点照样是绿底）。个人版（KeRing_SOLO）**保留**脚注和时刻。

**交互**

- 鼠标进小窗 **250ms** 后弹出预览（防路过误触）；离开小窗**和**预览 **300ms** 后收回
- 预览**在小窗旁边弹**，不是把小窗撑大——撑大时窗口会在鼠标底下变大，MouseEnter/Leave 来回打架、疯狂闪
- 方向自适应：右边放不下就往左弹，下面放不下就往上顶
- **单击小窗 = 展开/收起**（触屏/一体机没有 hover，必须留这条路）；**双击 = 打开主窗口**；**拖动**记住位置
- **不抢焦点**：`WS_EX_NOACTIVATE` + `ShowWithoutActivation`（上课时不能被打断），
  `WS_EX_TOOLWINDOW`（不进 Alt+Tab）、`ShowInTaskbar = false`、`Opacity = 92%`
- **首次贴在屏幕右侧、垂直居中**（不是右下角——右下角常被输入法/通知区压着）；位置存配置，
  换屏幕/改分辨率后跑到屏幕外就自动回到默认位置

**开关**：设置对话框里的"显示悬浮窗"、托盘菜单里的"显示悬浮窗"——两处是同一个配置项。

**实现**（都在 UI 层，不动数据链路）

| 文件 | 干什么 |
| --- | --- |
| `UI/ScheduleRender.cs` | **共用规则**：格子里写什么、什么颜色、"哪一节正在上"、"有没有周末课" |
| `UI/WeekGridView.cs` | 只读的全周课表控件（自己 GDI+ 画，不用 DataGridView：预览要紧凑、要一次画完、不要选中框和滚动条） |
| `UI/WeekPreviewForm.cs` | 预览窗（无边框 + 不抢焦点 + 只读） |
| `UI/FloatingForm.cs` | 小窗：今日列表、悬停计时、拖动、位置记忆、点击展开、表头图钉 |
| `App/AppConfig.cs` | `FloatingEnabled` / `FloatingLeft` / `FloatingTop` / `FloatingOpacity` / `FloatingShowWeekOnHover` / `FloatingTopMost` |
| `UI/MainForm.cs` | 建/关悬浮窗；**数据由它推过去**（`PushFloating`，每秒跟着界面刷）；托盘菜单加一项 |

**关键原则**：悬浮窗**不自己取数、不自己算提醒**——它只是"同一份 `WeekSchedule` 的另一个视图"。
否则会出现"主窗口和悬浮窗显示不一致"这种最难查的问题。

**跟个人版（KeRing_SOLO）的差别只有一处**：个人版的小窗和预览里还有**晨读 / 课1 / 课2 值班行**
（老师个人才有值班），班级版没有——班级版整张表就是一个班的课。

**宽度：124（个人版是 210）**。使用方 2026-09-16 先要求"窄一点"，再去掉脚注和右上角时刻，
最后明确"**按两个字就行**"，于是宽度是从剩下的内容倒推出来的——微软雅黑、96 DPI 实测：

| 元素 | 实测文字宽 | 位置约束 |
| --- | --- | --- |
| 表头"今天 周三"（11 磅粗体） | 73 | 左边距 10 + 标题 73 + 间隙 4 + 图钉 18 + 右边距 10 = **115 ← 瓶颈** |
| 一行"08:50 美术"（两字学科） | 37 | 12 + 46（时刻）+ 4 + 37 + 10 = 109 |
| 一行"08:50 信息课"（三字） | 51 | 12 + 46 + 4 + 51 + 10 = 123 |
| 一行"08:50 信息技术"（四字） | 65 | 12 + 46 + 4 + 65 + 10 = 137 → **放不下，会变省略号** |

**结论：小窗已经比一行课还窄不了了——是表头（"今天 周三" + 图钉）在撑着。**
要再窄只能先动标题（比如只写"周三"）或把图钉缩小/挪到别处。124 = 表头 115 留 9 像素余量，
顺带让**三个字**的学科名也放得下；四个字的会截成"信息…"（使用方已确认现在全是两字，接受这个边界）。
改宽度只改 `FloatingForm.PanelWidth` 这一个常量，改完记得回来更新这张表。

**这次踩的坑**（都修了，写下来省下次）：

1. **悬浮窗建出来了但看不见**（`IsWindowVisible = false`，日志却写着"已显示"）：把 `Owner` 设成主窗口、
   又在 `OnLoad` 里 `Show()`——那时**主窗口自己还没真正显示**，Windows 就不显示"被拥有的窗口"。
   改法：**不设 Owner**（改成把主窗口引用传进来）+ 推迟到 `OnShown` 再建。
2. **改高度是往下长的，会把窗口顶出屏幕**：默认位置是按"当时的高度"算的，课表行数一变就长高，底边出屏。
   改法：`SetData` 里改完高度就 `ClampToScreen()`；主窗口里**先 SetData 定尺寸、再 ApplyPosition 摆位置**。
3. **预览里"第1节 / 08:50"那两行小字被裁掉**：行高 34 装不下 10 磅两行字（TextRenderer 按行高裁）。
   改法：行高 38、时刻那行用 `UiFont.Small`（8.5 磅）。
4. **图钉点了没反应，用"标志位 + MouseUp"判断永远不触发**：实测 WinForms 的事件顺序是
   **MouseDown → MouseClick → MouseUp**（不是文档里写的 Down→Up→Click）。改法：**判断直接放在 MouseClick 里**。
5. **"取消置顶"了它还盖在别人上面**：`TopMost = false` 只清掉"总在最上"这个属性，**窗口仍停在原来的 z 序位置**。
   改法：取消置顶（以及**默认不置顶时刚显示出来**）都要**主动沉一次**
   （`SetWindowPos(HWND_BOTTOM, …, SWP_NOACTIVATE)`）——`OnShown` 里那次是默认行为的关键，
   少了它就会出现"明明没置顶，一开机还是压在所有窗口上面"。
   另外**不置顶状态下点它**会把它抬到普通窗口上面（`HWND_TOP` + `SWP_NOACTIVATE`，不抢键盘焦点），
   预览窗弹出来时也会抬一下，否则沉在最下面时"点了没反应"。
6. **预览的课表"只有竖线、没有网格"**（使用方 2026-09-16 反馈，附了截图）：
   `WeekGridView.OnPaint` 里只画了外框、表头下面那条线和每一列的竖线，**一行一条的横线漏了**。
   改法：画行的循环里把每行的下边界连同"上下午色带的下边界"记进 `rowLines`，最后统一补画；
   **最后一行那条跳过**——它就是控件底边，由外框画，画了底边会变成两像素粗的一条。

### 课表数据的结构（当前演示格式）

正式接口还没定，现在的 `IScheduleSource` 实现读的是这样一个 JSON 文件（**全校课表**）：

```json
{
  "generated_at": "2026-09-13T21:45:00+08:00",
  "periods": [
    { "index": 1, "start": "08:00", "end": "08:45" },
    { "index": 2, "start": "08:55", "end": "09:40" }
  ],
  "classes": [
    {
      "id": "class-1",
      "name": "一(1)班",
      "entries": [
        { "weekday": 1, "period": 1, "course": "语文" },
        { "weekday": 1, "period": 2, "course": "数学" }
      ]
    },
    {
      "id": "class-2",
      "name": "一(2)班",
      "entries": [ ]
    }
  ]
}
```

| 字段 | 含义 |
| --- | --- |
| classes | 全校所有班级。`id` 是程序记住"这台机器是哪个班"用的，**改名字不影响，换 id 才算换班** |
| name | 界面上显示的名字 |
| entries | 该班课程落在星期几的第几节；`course` 为空表示空堂，不生成打铃点 |
| periods | 节次编号。**具体时刻不用这里的 start/end**，由作息方案表决定（见约定 1） |

一句话：**课表数据负责"第几节上什么课"，作息方案负责"第几节是几点"。**
所以同一份课表数据可以发给低年级和高年级两种教室，只要各机器上的方案设对。

**旧格式兼容**：如果 JSON 里没有 `classes` 但有顶层 `entries`，会被当成"只有一个班的学校"，
班名自动取"默认班级"。这是为了兼容数据目录里已经生成过的旧 `schedule.json`。

## 六、数据与文件位置

### 交付物

**一个 exe**：`bin\Release\net472\KeRing.exe`（依赖和铃声都在里面，当前构建约 1003 KB / 1026560 字节）。
`dist\KeRing.exe` 是同一份的干净副本，专门用来交付，**并且已提交进仓库**，
克隆下来不用编译就能直接拿这个文件用。
拷到目标机任何目录双击即可，**不需要装运行时，也不需要其它文件**。

> ⚠ `dist\KeRing.exe` 是**构建产物**，改了代码必须重新 `dotnet build -c Release` 并把它覆盖过去，
> 否则仓库里那个 exe 会是旧版本。提交前建议核对一下 `dist` 和 `bin` 两份 exe 的哈希是否一致：
> `(Get-FileHash dist\KeRing.exe).Hash -eq (Get-FileHash bin\Release\net472\KeRing.exe).Hash`
>
> 注意这个比对只在**同一台机器**上验"dist 是不是刚编出来的那份"。
> 拿新编的去比对仓库里那版 dist 没有意义——**不同版本的 SDK 编出来的字节不一样**
> （实测：同一份源码用 SDK 9 和 SDK 8 编，exe 大小能差好几 KB）。

### 运行时产生的文件

全部在数据目录，**exe 旁边不会多出任何东西**：

| 路径 | 说明 |
| --- | --- |
| `C:\ProgramData\KeRing\kering.config.json` | 配置（首次运行生成） |
| `C:\ProgramData\KeRing\logs\日期.log` | 日志，保留 30 天，自动清理 |
| `C:\ProgramData\KeRing\schedule.json` | 演示用的课表数据，**只有配置里没填接口地址时才生成/使用** |
| `C:\ProgramData\KeRing\schedule-cache.json` | **最后一次成功抓到的真实课表**（约 330 KB）。开机接口取不到时先拿它顶上，状态栏标"数据：缓存 xx:xx" |
| `C:\ProgramData\KeRing\audio\ding.wav` | 可选：现场替换的铃声；不放就用 exe 内嵌的那份 |

数据目录的选择逻辑在 `App/AppPaths.cs`：优先 `%ProgramData%\KeRing`（整机一份、位置好找），
没有写权限就退回 `%LocalAppData%\KeRing`，并在日志里写明。`--selftest` 会打印实际目录。

**课表缓存**：每次成功取到课表都会写一份 `schedule-cache.json`。
（原来评审时说"不做本地缓存"，是因为**当时数据源是本地文件**，读不到基本等于程序坏了；
现在数据来自网络，机器开机时接口可能还没通，所以留一份最近的顶上。详见
[课表接口采集方案.md](课表接口采集方案.md) 7.4。）
接口读失败时，除了这份缓存，内存里的上一份课表也会继续用来打铃，只是不落盘。

## 七、构建 / 运行 / 自检 / 打包

```powershell
dotnet build -c Release                 # 产出 bin\Release\net472\KeRing.exe（单文件）
KeRing.exe --selftest                   # 无界面自检，返回码 = 问题数，0 表示全过
KeRing.exe --say 语文                    # 只播报一次，用来在目标机上确认真的能出声
```

**自检返回码 = 问题数**，部署到新机器后建议先跑一次。
自检里会打印**数据源里有多少个班、本机用的是哪一个班**，以及该班今天的打铃点——
在目标机上核对"这台机器有没有选错班"就靠这个。

### 改完代码必须做的三件事（使用方 2026-09-16 明确要求）

1. `dotnet build -c Release`（**必须先杀掉正在跑的 KeRing.exe**，不然 exe 被占用、覆盖会失败）
2. 把 `bin\Release\net472\KeRing.exe` **覆盖到 `dist\KeRing.exe`**——`dist` 那份是交付物、已经入库，
   不覆盖的话仓库里就还是旧版本；需要的话再拷一份到桌面
3. **提交并推送**：`git add -A` → `git commit` → `git push origin main`

**每次改完都要走完这三步，别把改动攒在本地。** 推送前建议顺手核对一下
`(Get-FileHash dist\KeRing.exe).Hash -eq (Get-FileHash bin\Release\net472\KeRing.exe).Hash`。

### 换铃声

- 母本在 `Assets/bell.wav`，编译时内嵌进 exe（改它需要重新编译，影响所有机器）
- 单台机器换：把 `ding.wav`（wav 或 mp3 都行）放到 `C:\ProgramData\KeRing\audio\`，程序优先用这个文件

| 风险 | 说明与应对 |
| --- | --- |
| 中文音色缺失 | 语音走系统 SAPI5，目标机没装中文语音包就**静默无声音**。`--selftest` 会报"可用中文音色 0 个"。本机只有 1 个（Microsoft Huihui） |

  **③** 周一到周五出现空课表（接口抽风）时**不覆盖**现有数据，只记日志。
  教室机器必须在校园网内才连得上 `10.40.1.1`。接口细节与改版历史见
  [课表接口采集方案.md](课表接口采集方案.md) |
| 还原卡 / 冰点还原 | 重启后配置和日志被还原。需要可持久化目录，或接受每次重配 |
| 杀软误报 | 单文件 exe（内嵌程序集、运行时内存加载）本身就是容易被误报的形态。**正解是代码签名证书**，不是靠换打包方式 |
| 音频被独占 | 别的程序占用独占模式音频时播报会失败，有日志和界面提示 |
| 系统时间不准 | **已处理**：全程序用 `AppClock` 取时间，按 NTP → 教务接口 `Date` 头 → 本机 的优先级自动修正（见约定 13）。残留风险：教室机器若**既连不上 NTP、又连不上教务服务器**，就只能用本机钟，这时错了没人知道——所以部署检查清单里仍然要求确认系统时间。另外那台教务服务器自己**慢 14 秒**，只当兜底 |

## 十、踩过的坑（省你时间）

按遇到顺序，都是实际踩过并解决的：

1. **WinForms 自动缩放不可靠。** net472 上 `AutoScaleDimensions` 会被重置成当前 DPI，缩放比例恒为 1，
   结果在 200% 缩放的 4K 屏上窗口只有预期物理尺寸的一半，行高不够把内容裁掉。
   现在 `AutoScaleMode = None`，所有尺寸自己乘 `UiScale.Factor`。**新增界面元素一定要用 `UiScale.S(...)`。**

2. **`.gitignore` 里的 `audio/` 会误伤 `App/Audio/`。** Windows 上 Git 默认不区分大小写，
   这个规则把源码目录一起忽略了，导致 `Announcer.cs` / `AudioController.cs` / `BellTone.cs`
   第一次提交时全都没进仓库。改 `.gitignore` 后务必 `git status` 确认源码目录还在。

3. **`AudioFileReader` 没有接收 `Stream` 的构造函数**（只有文件名）。
   内嵌铃声必须用 `WaveFileReader(stream)`（只支持 wav），现场替换的铃声才用 `AudioFileReader(path)`（wav/mp3 都行）。

4. **`.NET 6+` 模板的写法在 net472 上不存在**：`ApplicationConfiguration.Initialize()` 要换成经典三行
   （`EnableVisualStyles` + `SetCompatibleTextRenderingDefault` + `Run`），并且要关掉 `ImplicitUsings`。

5. **`<LangVersion>latest</LangVersion>` 必须显式写**，否则退回 C# 7.3，文件作用域命名空间之类的写法直接编不过。

6. **触摸控件的"选中项"要在建按钮之前判定。** `TouchChoice` 第一版默认值 0 在匹配之前就占了第一个按钮，
   导致两个按钮都显示成选中。

7. **长按连发不能只靠 MouseUp 停止。** 松开事件丢失（触屏抬手被吞、鼠标移出控件）会让数值一直跑；
   现在每次 tick 都检查 `Control.MouseButtons` 是否还按着。

8. **自动化测 GUI 时**：窗口被收进托盘后 `Process.MainWindowHandle` 是 0（拿不到句柄）；
   窗口被别的窗口盖住时，按坐标点击会落到别人身上。可行的做法是先用 `SetWindowPos` 把窗口提为 TOPMOST
   再点，或者启动第二个实例（会通过命名事件唤出已有窗口）。

9. **`Remove-Item` 之类的删除命令在本环境会被安全策略拦下**，清理临时文件时改用别的方式或交给用户。

10. **GUI 子系统程序直接在 PowerShell 里调用拿不到输出，也拿不到退出码。**
    本项目 `OutputType=WinExe`，`& KeRing.exe --selftest`既不打印也不返回退出码（进程没有控制台）。
    正确做法：`Start-Process -Wait -PassThru -NoNewWindow -RedirectStandardOutput <文件>`，
    再用 GBK 读那个文件（程序按控制台默认代码页输出）。

11. **学校接口的 `kWeek=0` 只用来探测当前周，它的课表不能直接当数据用。**
    实测 `kWeek=0` 返回的 `dktkInfoAoa`（调课记录）是**空的**，拿到的是没叠加调课的基础课表。
    正确做法是先探测出 `curKWeek`，再用那个周次请求一次——两次请求，别图省事合成一次。

## 十一、代码风格约定

- 注释用中文，解释"为什么这么做"而不是"这行在干什么"
- 注释里提到"约定""评审结论"的地方，都对应本文件第五节的条目；改代码时同步改本文件
- 危险操作（音量、注册表、写文件）一律带异常处理 + 日志，**不能让辅助功能失败导致主功能失败**
  （例子：提示音播不出来时仍然要播语音）
- 界面相关的异常不弹窗打断无人值守运行，走日志 + 状态栏

## 十二、不在范围内（评审确认不做的）

这些是和使用方逐条确认过的结论，**不要"顺手"实现**——每条都有当时的理由：

| 不做 | 理由 |
| --- | --- |
| 上课铃、下课铃、多铃型（眼保健操、大课间等） | 由使用方已有的打铃程序负责；本程序只做课前提醒 |
| 手动打铃 | 同上，别的铃不归本程序管 |
| 防系统睡眠、漏播检测与告警 | 使用方确认目标机不会睡眠 |
| ~~课表本地缓存~~ | 改了主意：**做了**。原来数据源是本地文件，"本地缓存"没意义；现在数据来自网络，需要一份最近的课表顶开机取不到数据的场景（见第六节）。 |
| 数据过期保护 | 仍然不做：缓存**没有过期时间**。机器长期停机、接口又刚好不通时，会拿旧课表顶上；但状态栏一直显示缓存的取到时刻，判断交给管理员。 |
| 假期与调课的特殊处理 | 假期机器关机，不涉及 |
| 数据变化检测（哈希比对） | 暂不做，但**理由已经变了**：原来写的是"数据源本地、刷新成本低"；现在数据来自网络，做它能省掉"内容没变也重建界面 + 重写 330 KB 缓存"的开销。属于可做可不做的优化，列在待办里等你定 |
| 手动导入课表 | 走数据源即可 |
| 独立配置界面、界面锁定、密码退出 | 暂不需要；配置就是一个 JSON 文件 |
| 全屏大屏视图 | 窗口是给管理员看的工具，不是给学生看的展示屏 |
| 崩溃自恢复 / 看门狗 | 每天开机启动一次，异常由人发现 |
| 系统时间偏差检查 | 改了主意：**做了**。教室机器确实有钟不准的，用 NTP + 教务接口 `Date` 头自动修正（见约定 13）。原本"不做"是因为当时没有可信的时间源 |
| 程序自更新 | 手工替换那一个 exe |
| 课表抓取与解析规则本身 | 由使用方提供接口 |
| 请假考勤点名、手机端 / 网页端、多机状态同步、非 Windows 平台 | 与项目目标无关 |
| 改用 .NET 8/10 自包含部署 | 体积（52 MB vs 约 1 MB）与 Win7 支持，见第三节 |

## 十三、部署到教室机器的检查清单

1. 把 `KeRing.exe` 拷到**机器硬盘上的固定目录**（别放 U 盘——自启项登记的是它的完整路径，U 盘一拔就失效）
2. 双击运行，确认窗口和托盘图标出现
3. 首次运行会弹**选择班级**——选这台机器要服务的班；以后想改在"设置 → 班级"里换。
   如果没弹（说明配置里已经有班级了），先去设置里确认当前是哪个班
4. 点"设置"确认**班级选对了**——时段方案会跟着班级自动定（一二年级低年级、三到六年级高年级），
   对话框里那一行是只读的，看一眼对不对就行
5. 命令行跑一次 `KeRing.exe --selftest`，确认：
   - 打印的"数据目录"是预期位置
   - 打印的**班级列表和"本机使用"的班**是这一台对的那个班
   - "音频设备"不是"无可用播放设备"
   - "可用中文音色" ≥ 1（是 0 就得装中文语音包，否则语音静默无声）
   - "提示音来源"符合预期
   - 返回码为 0（返回码 = 问题数）
6. 确认机器**已开启自动登录**（否则 `HKCU\Run` 在登录前不会执行）
7. 确认系统时间大致准确（程序会自动校时，但那是兜底：**如果这台机器既连不上 NTP、
   又连不上教务服务器，就只能用本机钟**）。自检报告里 `[10] 时间` 会写明用的是哪个源、
   偏差多少；NTP 一栏显示"全部不可达"就说明得给学校内网 NTP 或域控地址
8. 开机自启默认已开启；重启一次，验证程序会自己起来，且**不再弹选班框**
