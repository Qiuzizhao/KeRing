# KeRing 开发交接说明

**这是项目唯一的技术文档。接手开发、改代码、部署之前请完整读一遍。**
它记录了：环境要求、技术选型的理由、项目结构、不能违反的约定、待办、已知风险，以及前人踩过的坑。

---

## 一、这是什么 · 现在什么状态

教室一体机用的打铃程序。读课表，在**每节课开始前 7 分钟**播报
「下节课，×××，请同学们做好课前准备」（提示音 + 语音）。

**当前状态：功能完整、可交付、可运行。**

| 事项 | 状态 |
| --- | --- |
| 功能开发 | 完成（见下方功能清单） |
| 单文件打包 | 完成，产出 964 KB 的一个 exe |
| 接入正式课表接口 | **未完成**，等使用方提供接口规则与示例 |
| 低年级作息的真实时间 | **未完成**，现在是占位值 |
| 换机测试（教室机器实测） | 未做 |

### 功能清单

- 周课表显示：行 = 第 1..N 节（含作息时刻），列 = 周一到周日
- 正在上的课标红、下一个提醒点标绿
- 上午/下午之间有一条深蓝分隔色带（位置可配）
- 周六周日没有课时自动隐藏两列，窗口宽度跟着收窄
- 每节课前 7 分钟播报（分钟数可配）
- 作息方案（低年级 / 高年级）二选一，时刻由程序内置方案表决定
- 播报前把系统音量临时提到设定值，播完恢复原值（含静音状态）
- 托盘常驻、关窗不退出、开机自启（默认开）
- 单实例（整机唯一）、静音开关、手动更新课表、手动测试播报
- 换铃声（母本进仓库、内嵌进 exe、现场可替换）
- 无界面自检 `--selftest`、单次播报 `--say`

## 三、技术选型（以及为什么是这些）

| 项目 | 选型 | 备注 |
| --- | --- | --- |
| 语言 / UI | C# + WinForms | 代码构建界面，不用设计器；原生托盘、表格，开发量最小 |
| 目标框架 | **.NET Framework 4.7.2** | 见下方"为什么不用 .NET 8/10" |
| 语言版本 | `<LangVersion>latest</LangVersion>` | 不显式设会退回 C# 7.3，现代写法直接编不过 |
| Nullable / ImplicitUsings | 都关闭 | net472 上隐式 using 会引来找不到类型的编译错误 |
| 语音合成 | **System.Speech**（框架自带，SAPI5） | **不是 NuGet 包**，用 `<Reference Include="System.Speech" />` 引用 |
| 音量与播放 | **NAudio 2.2.1** | Core Audio API 控制系统音量；播放提示音 |
| 配置与课表解析 | **Newtonsoft.Json 13.0.3** | |
| 单文件打包 | **Costura.Fody 6.0.0** | 把依赖的托管程序集嵌进 exe，运行时从内存加载 |
| 定时 | `System.Timers.Timer`，1 秒轮询 | 每次按系统时钟重算，不累加间隔（避免漂移） |
| 自启 | `HKCU\...\Run` | 不需要管理员权限 |
| 单实例 | `Global\` 命名 Mutex + 命名事件 | 整机唯一；命名事件用来唤出已有窗口 |

### 为什么不用 .NET 8 / 10

- Windows 自带的是 **.NET Framework**，不含 .NET 8/10。用新版就得自包含，**52 MB 自包含单文件 vs 现在 964 KB**
- .NET 8 及以上**完全不支持 Win7**；4.7.2 兼容到 Win7（装一次即可）
- 定 4.7.2 而不是 4.8：4.7.2 的程序在 4.8 机器上照跑，反过来不行。Win10 1809 LTSC 这类一体机常见系统自带 4.7.2，**定低一档覆盖更广**
- 代价：生态偏旧、少数新语法要垫片。本项目的需求用不到新特性

### 单文件是怎么做到的

.NET Framework **没有**官方单文件发布。这里用 `Costura.Fody` 把依赖的托管程序集作为资源嵌进 exe，
运行时通过 `AssemblyResolve` 从内存加载。`FodyWeavers.xml` 里一行 `<Costura />` 就是全部配置。

**前提是所有依赖都是托管程序集**——本项目满足（NAudio 全是托管代码，通过 P/Invoke 调系统 API，没有原生 dll）。

## 五、关键约定（改代码前必须知道）

这几条是评审时和使用方逐条确认下来的，**不要凭直觉改**：

1. **时刻由程序里的作息方案表决定，课表数据只提供"星期几、第几节、上什么课"。**
   数据源不知道这台机器属于哪个年级，所以 `App/GradeSchemes.cs` 是时刻的唯一来源，
   数据里即使带了 `start/end` 也会被覆盖（见 `MainForm.ApplyGradeScheme`）。

2. **数据源以 `IScheduleSource` 为界。** 正式接入时只写一个实现类，把"取数 + 解析"都放进去，
   在 `MainForm.RefreshSchedule` 里换掉即可，其余代码不动。配置里已预留 `ScheduleApiUrl`。

3. **单实例是整机唯一的**（`Global\` 命名锁）。一台机器只允许一个实例，即使程序被拷到两个目录、
   或同一账号在另一个会话（远程桌面）再次登录。拿不到全局权限时才退回本会话锁，并写日志。

4. **音量是"临时提升 + 原样恢复"。** 提升和恢复都写在 `Announcer.Announce` 里，
   恢复在 `finally`，包含静音状态。**不要改成启动时永久拉满**——会覆盖用户设置。

5. **静音只在本次运行有效**，重启自动恢复不静音。这是故意的：静音被遗忘会导致铃长期不响还没人发现。

6. **错过的打铃点不补播**，只记日志（`Scheduler.Rebuild` 会把过去的点标记为已触发）。

7. **周六周日作为一组**：都没有课就一起隐藏，任一天有课就一起显示；
   并且**窗口宽度跟着可见天数走**（列宽固定 124），不是把剩下的列拉宽。

8. **所有界面尺寸都走 `UiScale.S(...)`**，不要直接写像素值。
   WinForms 的自动缩放在这套代码上不可靠（见下方"踩过的坑"）。

9. **程序不往自己旁边写任何东西。** 运行时文件都放数据目录（见下一节），
   因为程序是单文件，要能在只读目录里跑。

10. **课表接口接入前，`schedule.json` 只是演示数据**，正式上线后这个文件可能不存在。

### 课表数据的结构（当前演示格式）

正式接口还没定，现在的 `IScheduleSource` 实现读的是这样一个 JSON 文件：

```json
{
  "generated_at": "2026-09-13T21:45:00+08:00",
  "periods": [
    { "index": 1, "start": "08:00", "end": "08:45" },
    { "index": 2, "start": "08:55", "end": "09:40" }
  ],
  "entries": [
    { "weekday": 1, "period": 1, "course": "语文" },
    { "weekday": 1, "period": 2, "course": "数学" }
  ]
}
```

| 字段 | 含义 |
| --- | --- |
| periods | 节次编号。**具体时刻不用这里的 start/end**，由作息方案表决定（见约定 1） |
| entries | 课程落在星期几的第几节；`course` 为空表示空堂，不生成打铃点 |

一句话：**课表数据负责"第几节上什么课"，作息方案负责"第几节是几点"。**
所以同一份课表数据可以发给低年级和高年级两种教室，只要各机器上的方案设对。

## 六、数据与文件位置

### 交付物

**一个 exe**：`bin\Release\net472\KeRing.exe`（约 964 KB，依赖和铃声都在里面）。
`dist\KeRing.exe` 是同一份的干净副本，专门用来交付。
拷到目标机任何目录双击即可，**不需要装运行时，也不需要其它文件**。

### 运行时产生的文件

全部在数据目录，**exe 旁边不会多出任何东西**：

| 路径 | 说明 |
| --- | --- |
| `C:\ProgramData\KeRing\kering.config.json` | 配置（首次运行生成） |
| `C:\ProgramData\KeRing\logs\日期.log` | 日志，保留 30 天，自动清理 |
| `C:\ProgramData\KeRing\schedule.json` | 演示用的课表数据（正式接入接口后不需要） |
| `C:\ProgramData\KeRing\audio\ding.wav` | 可选：现场替换的铃声；不放就用 exe 内嵌的那份 |

数据目录的选择逻辑在 `App/AppPaths.cs`：优先 `%ProgramData%\KeRing`（整机一份、位置好找），
没有写权限就退回 `%LocalAppData%\KeRing`，并在日志里写明。`--selftest` 会打印实际目录。

**没有本地课表缓存**——数据源读失败时用内存里的上一份继续跑并提示，不落盘（评审时定的：断网场景不考虑）。

## 八、待办（下一步该做什么）

按优先级：

1. **接入正式课表接口**（最高优先）。需要先拿到使用方的接口规则和参考示例，做法见"关键约定"第 2 条。
2. **拿到低年级的真实作息时间**，替换 `App/GradeSchemes.cs` 里的 `JuniorTimes`（现在是占位值）。
3. **换真正的提示音**：把 `Assets/bell.wav` 换成学校的铃声，重新编译。
4. **换机测试**：拷 exe 到教室机器，跑 `--selftest`，确认音频设备与中文音色。
5. 可选：**语音改成"提前合成 + 片段拼接"**（现在是到点现场调 TTS；提前合成能让播报时刻几乎不失败、
   时长可预知、音色缺失在加载时就能发现）。
6. 可选：加 GitHub Actions，推送时自动编译一遍，防止"推上去的代码编不过"。

## 九、已知风险

| 风险 | 说明与应对 |
| --- | --- |
| 中文音色缺失 | 语音走系统 SAPI5，目标机没装中文语音包就**静默无声音**。`--selftest` 会报"可用中文音色 0 个"。本机只有 1 个（Microsoft Huihui） |
| 目标机没有 4.7.2 | Win10 1803 以后和 Win11 都自带；Win7 需装一次（还要先打 SHA-2 补丁）。准备离线安装包 |
| 目标机未自动登录 | `HKCU\Run` 在登录前不执行。锁屏、息屏没关系，**注销等于杀掉会话** |
| 还原卡 / 冰点还原 | 重启后配置和日志被还原。需要可持久化目录，或接受每次重配 |
| 杀软误报 | 单文件 exe（内嵌程序集、运行时内存加载）本身就是容易被误报的形态。**正解是代码签名证书**，不是靠换打包方式 |
| 音频被独占 | 别的程序占用独占模式音频时播报会失败，有日志和界面提示 |
| 系统时间不准 | 打铃完全依赖本机系统时间（`DateTime.Now`），**目前没有任何检测**。时间偏差会让铃整体早/晚，日期或星期错会取错那天的课表，时区错会差整整 8 小时。若要做，最合适的时间源是课表接口的 HTTP `Date` 头（免费、不额外发请求、不需要权限） |

## 十、踩过的坑（省你时间）

按遇到顺序，都是实际踩过并解决的：

1. **WinForms 自动缩放不可靠。** net472 上 `AutoScaleDimensions` 会被重置成当前 DPI，缩放比例恒为 1，
   结果在 200% 缩放的 4K 屏上窗口只有预期物理尺寸的一半，行高不够把内容裁掉。
   现在 `AutoScaleMode = None`，所有尺寸自己乘 `UiScale.Factor`。**新增界面元素一定要用 `UiScale.S(...)`。**

2. **`.gitignore` 里的 `audio/` 会误伤 `App/Audio/`。** Windows 上 Git 默认不区分大小写，
   这个规则把源码目录一起忽略了，导致 `Announcer.cs` / `AudioController.cs` / `BellTone.cs`
   第一次提交时全都没进仓库。改 `.gitignore` 后务必 `git status` 确认源码目录还在。

3. **`AudioFileReader` 没有接收 `Stream` 的构造函数**（只有文件名）。
   内嵌铃声必须用 `WaveFileReader(stream)`（只支持 wav），现场替换的铃声才用 `AudioFileReader(path)`（wav/mp3 都行）。

4. **`.NET 6+` 模板的写法在 net472 上不存在**：`ApplicationConfiguration.Initialize()` 要换成经典三行
   （`EnableVisualStyles` + `SetCompatibleTextRenderingDefault` + `Run`），并且要关掉 `ImplicitUsings`。

5. **`<LangVersion>latest</LangVersion>` 必须显式写**，否则退回 C# 7.3，文件作用域命名空间之类的写法直接编不过。

6. **触摸控件的"选中项"要在建按钮之前判定。** `TouchChoice` 第一版默认值 0 在匹配之前就占了第一个按钮，
   导致两个按钮都显示成选中。

7. **长按连发不能只靠 MouseUp 停止。** 松开事件丢失（触屏抬手被吞、鼠标移出控件）会让数值一直跑；
   现在每次 tick 都检查 `Control.MouseButtons` 是否还按着。

8. **自动化测 GUI 时**：窗口被收进托盘后 `Process.MainWindowHandle` 是 0（拿不到句柄）；
   窗口被别的窗口盖住时，按坐标点击会落到别人身上。可行的做法是先用 `SetWindowPos` 把窗口提为 TOPMOST
   再点，或者启动第二个实例（会通过命名事件唤出已有窗口）。

9. **`Remove-Item` 之类的删除命令在本环境会被安全策略拦下**，清理临时文件时改用别的方式或交给用户。

## 十一、代码风格约定

- 注释用中文，解释"为什么这么做"而不是"这行在干什么"
- 注释里提到"约定""评审结论"的地方，都对应本文件第五节的条目；改代码时同步改本文件
- 危险操作（音量、注册表、写文件）一律带异常处理 + 日志，**不能让辅助功能失败导致主功能失败**
  （例子：提示音播不出来时仍然要播语音）
- 界面相关的异常不弹窗打断无人值守运行，走日志 + 状态栏

## 十二、不在范围内（评审确认不做的）

这些是和使用方逐条确认过的结论，**不要"顺手"实现**——每条都有当时的理由：

| 不做 | 理由 |
| --- | --- |
| 上课铃、下课铃、多铃型（眼保健操、大课间等） | 由使用方已有的打铃程序负责；本程序只做课前提醒 |
| 手动打铃 | 同上，别的铃不归本程序管 |
| 防系统睡眠、漏播检测与告警 | 使用方确认目标机不会睡眠 |
| 课表本地缓存、数据过期保护 | 断网场景不考虑；假期机器关机 |
| 假期与调课的特殊处理 | 假期机器关机，不涉及 |
| 数据变化检测（哈希比对） | 数据源本地、刷新成本低，暂不需要 |
| 手动导入课表 | 走数据源即可 |
| 独立配置界面、界面锁定、密码退出 | 暂不需要；配置就是一个 JSON 文件 |
| 全屏大屏视图 | 窗口是给管理员看的工具，不是给学生看的展示屏 |
| 崩溃自恢复 / 看门狗 | 每天开机启动一次，异常由人发现 |
| 系统时间偏差检查 | 未做，需要时再加（见第九节"已知风险"） |
| 程序自更新 | 手工替换那一个 exe |
| 课表抓取与解析规则本身 | 由使用方提供接口 |
| 请假考勤点名、手机端 / 网页端、多机状态同步、非 Windows 平台 | 与项目目标无关 |
| 改用 .NET 8/10 自包含部署 | 体积（52 MB vs 964 KB）与 Win7 支持，见第三节 |

## 十三、部署到教室机器的检查清单

1. 把 `KeRing.exe` 拷到**机器硬盘上的固定目录**（别放 U 盘——自启项登记的是它的完整路径，U 盘一拔就失效）
2. 双击运行，确认窗口和托盘图标出现
3. 点"设置"，把**时段方案选对**（低年级 / 高年级）——这决定上下课时刻
4. 命令行跑一次 `KeRing.exe --selftest`，确认：
   - 打印的"数据目录"是预期位置
   - "音频设备"不是"无可用播放设备"
   - "可用中文音色" ≥ 1（是 0 就得装中文语音包，否则语音静默无声）
   - "提示音来源"符合预期
   - 返回码为 0（返回码 = 问题数）
5. 确认机器**已开启自动登录**（否则 `HKCU\Run` 在登录前不会执行）
6. 确认系统时间准确（程序自己不做任何校时）
7. 开机自启默认已开启；重启一次，验证程序会自己起来
